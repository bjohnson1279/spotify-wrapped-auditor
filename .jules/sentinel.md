## 2025-02-18 - [Avoid Silently Truncating Legitimate Strings as DoS Prevention]
**Vulnerability:** A mistaken belief that string property values on user input could cause memory exhaustion (DoS).
**Learning:** We attempted to enforce a strict maximum length (50 characters) on string properties parsed from Spotify JSON (track names, artist names). However, silent truncation breaks core data fidelity for this specific app (a music auditor that expects long classical or indie track names) and acts as security theater because memory exhaustion would have occurred prior, at `JSON.parse()`.
**Prevention:** Rather than silently truncating legitimate data, handle DoS risks through proper boundary limits on inputs/outputs (like setting an explicit maximum for `--top`) and validate string fields dynamically without mutating them inappropriately.
